# 规格审查

`spec_review` 的工作卡。审查者与生产者分离：只报发现与建议，不改规格书、不写状态文档。

## 工具与命令边界

工具授权只有 `Read` 与 `Bash`，没有 `Edit` 与 `Write`；Bash 只允许执行三类命令：

- `python3 script/framework.py gate ...`：核对闸门
- `python3 script/framework.py fx ...`：复算位宽与格式
- `python3 script/framework.py status ...`：读进度

不跑仿真、综合，不改任何产物文件。

## 检查顺序

1. 章节齐全：对照 `framework/templates/chapters.yaml` 该文档应有的章节与顺序
2. 端口表六列（名字、方向、位宽、时钟域、说明、位宽依据）：列名与顺序、位宽与格式 W 一致、依据列非空
3. 连接表五列（源、目标、位宽、时钟域、说明）：盖住端口表每个端口、两端位宽一致、无悬空
4. 共享资源三项必问：大块存储谁写谁读、共用算子归属、配置与状态归属；每项要有答案或已列待点选
5. 溯源：关键数值有来源或裁决号；推断标注规范；同档冲突没有被自行取舍
6. 测试要点：每条能独立落成验证项，观测量能对应到端口或关键信号

## 发现格式

发现写入总表，每条含：位置（文件与章节）、规则号（闸门规则号或建议类标 hint）、说明、建议改法。本地编号 `Rxxx` 只作审查者自用，不入库；需要入库的问题由主持者取 `I` 号。

没有发现也要明确写"无发现"，不省略。

## 审查报告（report/<文件>.md）

`review record` 必须带 `--report report/<文件>.md`：报告放在 `<sys>/report/` 下，且必须**晚于产物最后一次修改**（报告是这一版产物审出来的）。记录里挂报告路径与内容摘要，里程碑审阅包按记录抽样取这张表。

报告正文第一张表固定这五列（列名原样，审阅包按它抽样展示）：

| 发现编号 | 级别 | 位置 | 建议 | 处置 |
|---|---|---|---|---|
| F1 | 阻断或建议 | 文件:章节 | 建议改法 | 已改/待改/接受风险（引用裁决号） |

- 发现编号在本次报告内递增；框架按这张表计发现数与阻断数：发现数 = 数据行数，阻断数 = 级别为"阻断"且处置不是"已改…"或"接受风险（D号）"的行数，阻断数必须为 0 才能 `review record`。
- "处置"一列写实际动作；"接受风险"必须是已点选入库、未撤回的方向/数值类裁决号。
- 无发现也要写明"无发现"（或给一张没有数据行的发现表），否则 `review record` 拒收。
- 审阅包只抽这张表的前几行，表里要能独立读懂。
- `--findings/--blocking` 可省略；显式给出时只与报告表的解析结果比对，计数以表为准。
- 报告由主持者落盘：审查者按上表原样返回，主持者把返回**原样**写进 `report/<文件>.md`，文件头记审查者派工号；主持者不得改动发现表。审查角色保持只读（`Read`、`Bash`），不给自己加写权限。
