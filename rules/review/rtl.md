# RTL 审查

`rtl_review` 的工作卡。只报发现与建议，不改 RTL、不改规格书、不写状态文档。

## 工具与命令边界

工具授权只有 `Read` 与 `Bash`，没有 `Edit` 与 `Write`；Bash 只允许执行三类命令：

- `python3 script/framework.py gate ...`：核对闸门
- `python3 script/framework.py fx ...`：复算位宽与格式
- `python3 script/framework.py status ...`：读进度

不跑仿真、综合，不改任何产物文件。

## 两种模式

- 模块模式（行 7）：规格与代码一致性——对照该模块规格书的端口表（不对照子系统规格书的模块摘要）逐项核对端口名、方向、位宽；再核 `rules/coding.md` 的文件头、结构顺序、命名前缀、`case` 的 `default`、时序块自赋值、复位后控制信号非 X；定点运算按 `fx` 复算移位与饱和
- wrapper 模式（行 8）：另核连接完整性——连接关系表与例化一一对应、无同名不同宽、直连线命名 `wir_<源>2<宿>_<信号>`、未使用输入接常量并注明原因、参数传递与规格书一致

## 发现格式

每条发现含：文件与行（或章节）、规则号（闸门规则号或建议类标 hint）、说明、建议改法；并标注类型：阻断（功能错误、接口不一致）或建议（风格、可维护性）。

没有发现也要明确写"无发现"，不省略。

## 审查报告（report/<文件>.md）

`review record` 必须带 `--report report/<文件>.md`：报告放在 `<sys>/report/` 下，且必须**晚于产物最后一次修改**（报告是这一版产物审出来的）。记录里挂报告路径与内容摘要，里程碑审阅包按记录抽样取这张表。

报告正文第一张表固定这五列（列名原样，审阅包按它抽样展示）：

| 发现编号 | 级别 | 位置 | 建议 | 处置 |
|---|---|---|---|---|
| F1 | 阻断或建议 | 文件:行（或章节） | 建议改法 | 已改/待改/接受风险（引用裁决号） |

- 发现编号在本次报告内递增（F1、F2…）；框架按这张表计发现数与阻断数：发现数 = 数据行数，阻断数 = 级别为"阻断"且处置不是"已改…"或"接受风险（D号）"的行数，阻断数必须为 0 才能 `review record`。
- "处置"一列写实际动作：已改（说明改在哪）、待改（写进在途调试事项）、接受风险（必须是已点选入库、未撤回的方向/数值类裁决号）。
- 无发现也要写明"无发现"（或给一张没有数据行的发现表），否则 `review record` 拒收。
- 报告可以附正文说明，但审阅包只抽这张表的前几行，所以表里要能独立读懂。
- `--findings/--blocking` 可省略；显式给出时只与报告表的解析结果比对，计数以表为准。
- 报告由主持者落盘：审查者按上表原样返回，主持者把返回**原样**写进 `report/<文件>.md`，文件头记审查者派工号；主持者不得改动发现表。审查角色保持只读（`Read`、`Bash`），不给自己加写权限。
