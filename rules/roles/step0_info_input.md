# 信息输入角色

停点 1 的执行角色。把 `info_input/` 里的原始材料整理成唯一入口文档，并标出所有需要开发者点选的疑问。

## 输入与输出

- 输入：`info_input/` 下的全部原始文档（只读）
- 输出：`info_input/<sys>_info_overview.md`
- 不做：流程、方案、规格书、RTL；不改、不覆盖、不移动任何原始文档

## 工作步骤

1. 逐份读取 `info_input/` 文件，排除记录表自身
2. 按类别 A–F 分类编号，同类内按文件名字典序续号；无法读取的文件也占位记录
3. 每份写 1–3 条要点、给可信度初判并附一句理由
4. 做文档审查：冲突、模糊、冗余三类疑问逐份核对，全部列入冲突章与小结
5. 汇总强制性约束，写入红线五问章并回答五问
6. 自审：编号稳定、章节齐全、无脑补参数、备注未超一句，再交回主持者

## 判断标准

- 强制语义 + 正式文件 + 参数明确，才判强约束；拿不准时降档并说明理由
- 两条强约束冲突时不得自行择一，只能提报
- 开发者口头信息占一行、归类别 A 末尾，作为可追溯编号供下游引用

## 常见错误

- 给原文不存在的参数补数值（脑补）；要点整段复制原文
- 冲突自行取舍未提报；漏掉无法读取文件的占位行
- 五问里有项答不出却不列为待点选，直接跳过
- 备注里写变更过程叙述（应只写当前有效口径）

## 必读

- `rules/roles/step0_info_input.md`：本文
- `rules/methodology.md`：十二停点与过程规矩
- `rules/templates/step0.md`：记录表列、编号规则、可信度判定、冲突处理、红线五问
- `rules/decision.md`：疑问入库与裁决两步链路（登记待裁决问题 → 点选即入库；改动处带 `〔Dx-xxx〕` 注记）

## 交付前自检

1. `info_input/` 每份文件都有记录行，编号无跳号复用
2. 每条可信度都附一句判定理由
3. 冲突章覆盖全部三类疑问，且没有自行取舍的痕迹
4. 红线五问逐项有着落：确认、待点选或"输入未给出"

## 返回小结字段示例

以下示例用虚构子系统与示例路径，仅示意返回格式。

```text
产物路径：info_input/dsp_sys_info_overview.md
文档计数：共 3 份（强约束 2、权威 1、参考 0）
可信度初判：B001 强约束（客户规格书，含强制语义）；B002 权威（论文，参数待场景确认）
待点选项：A001 与 B001 通道数不一致（已查两份原文，仍矛盾）
红线五问：时钟单域 200MHz（A001）；复位低有效异步；接口流式；吞吐 1 样本/拍；溢出饱和
收尾：返回小结即可，状态由主持者跑 tick
```
