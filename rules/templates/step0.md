# 信息总览模板

对应章节模型的 step0（停点 1）。产物是 `info_input/<sys>_info_overview.md`，是行 2 及以后读输入的唯一入口。

必填章节：输入文档、可信度、冲突、红线五问

## 输入文档章

记录表列固定为：编号、文件、要点、可信度、备注。

- 编号：类别字母 + 三位流水号（A001 起），见下节编号规则；编号是全流程引用输入依据的稳定 ID
- 文件：文件原名含扩展名，与 `info_input/` 实际文件逐一对应，不改名不缩写；开发者口头信息也占一行，文件列写"（开发者口头说明，无对应文档）"
- 要点：每份文档 1–3 条、每条一句话，只压缩不添加；禁止整段复制原文
- 可信度：三档之一，档位定义见可信度章；判定必须能给出一句话理由
- 备注：只记疑点、文档间冲突与时效，不超过一句；无法读取的文件也要占一行并注明原因

表格前可加一行统计（共 N 份：强约束 x、权威 y、参考 z）。单份文档含可执行参数、公式或时序时，在表后按编号展开小节，每份不超过五行，只写结论加出处。

编号规则：

- 类别字母 A–F：A 需求与设计交流（需求文档、邮件、会议纪要、变更请求）；B 算法（算法文档、定点化说明、论文）；C 协议与接口（协议、总线、接口时序图、数据手册）；D 规格与预算（规模、时钟、带宽、资源功耗预算）；E 测试与约束（用例要求、验收标准）；F 参考实现与资料（公共模块清单、参考设计、器件手册）
- 流水号三位起，同类内按文件名字典序续号；新文档在类别末尾续号，删除后空号保留不复用
- 开发者口头信息归入类别 A 末尾；增量更新时既有编号一律不动

## 可信度章

三档从高到低：

| 档位 | 定义 | 典型材料 |
|------|------|----------|
| 强约束 | 强制性，违反即不合格 | 客户规格、协议标准、经确认的决议邮件、验收标准 |
| 权威 | 专业可信但建议性，数值需结合场景确认 | 算法文档、论文、器件手册、参考实现说明 |
| 参考 | 仅背景理解，不构成设计依据 | 草稿、笔记、已被取代的旧版文档 |

判定顺序：先看强制语义（必须、不得、固定为、以…为准），再看文档性质（外部正式、内部资料、草稿），再看可执行性（有没有可执行的数值与参数），最后看时效（有没有更新版取代它）。强制语义加正式文件且参数明确判强约束；专业可信但语义为"建议/通常"或参数待定判权威；三者都弱判参考。可信度由角色初判，开发者定级为准，角色不得自动推翻。

## 冲突章

- 跨档冲突：强约束、权威、参考，低档让步，并注明让步理由
- 同档强约束冲突：不得自行取舍，写明双方出处，提报开发者点选
- 同档权威冲突：优先更正式来源，仍建议提报确认
- 新旧版本冲突：以新版本为有效版本，旧版可信度降为参考并指向新编号

三类疑问一律提报：信息冲突、信息模糊（缺关键参数）、信息冗余（同事实多处且口径不一致）。提报写明涉及编号、位置、类型与候选处置，不在文档间自行择一。

## 红线五问章

逐项过，有则确认、无则列待点选，不得跳过：

1. 时钟域与频率：单/多域、工作频率，或写"输入未给出"
2. 复位极性与释放：同步/异步、高/低有效、释放条件
3. 顶层数据与配置接口形态：流式、存储映射、寄存器，或"待行 3 概括"
4. 吞吐或节奏承诺：峰值样本率、帧周期，或"输入未约束"
5. 定点溢出策略：截断、饱和，或"未给出，待点选"
